# AGENTS.md — правила разработки Seyvix

Архитектура и протокол очередей: `docs/ARCHITECTURE.md`. Запуск и деплой: `README.md`.
Документация может отставать — источник истины код и `backend/app/core/config.py`.

## Подход
- TDD: сначала падающий тест на поведение через публичный API (HTTP, функции модуля),
  потом минимальный код, потом рефакторинг. Тесты не привязываются к деталям реализации.
- Чините причину, а не симптом: никаких `except Exception: pass`, подавленных
  предупреждений и спецслучаев под конкретный вход.
- Сначала вычитать, потом добавлять: удаляйте мёртвый код, дубли, шимы и устаревшие пути
  при каждом изменении. Новая зависимость — только с понятной причиной.
- Маленькие проверяемые шаги: каждый шаг оставляет тесты зелёными.
- Не ломайте работающие функции и формы ответов REST, на которые опирается `web/`.

## Backend (`backend/`)
- Python 3.13, mypy strict, ruff (line length 100). Логи — `get_logger(__name__)` (structlog),
  пользовательские ошибки — `AppError` (единый формат `{"error": {...}}`).
- Router тонкий: валидация → service → ответ. Бизнес-логика — в модуле.
- Модули общаются через `contracts.py` и события (`app/contracts/events`), не через
  внутренности друг друга.
- Event loop не блокируется: sync/CPU-работа — `asyncio.to_thread` или subprocess.
- Память ограничена: файлы стримятся, размеры ограничены, пагинация в SQL, без N+1.
- Фоновые задачи — по паттерну `app/platform/jobs.py`: claim + commit → работа без
  транзакции и блокировок → финализация каждой задачи короткой транзакцией. Постановка
  задач идемпотентна. Обработчики событий быстрые и не делают commit/rollback.
- Файлы — только через `StorageBackend` (`request.app.state.storage` / `ctx.storage`),
  всё по заметке — под `objects/{id}/`.
- AI — только через `app.modules.llm.client.get_ai_client(settings)`; при `None` функция
  деградирует без ошибок.
- Схема БД — ORM-модели (все индексы объявлены в моделях); миграции — Alembic
  (`uv run alembic revision --autogenerate`), проверяйте сгенерированный файл.
- Новая настройка — поле в `config.py` + строка в `.env.example`, если её нужно менять.

## Frontend (`web/`)
- React Router SPA + TanStack Query, строгий TypeScript. Данные — через `src/api`.

## Проверки (перед коммитом)
```bash
make testdb          # один раз: тестовый Postgres на :55432 (данные стираются)
make lint            # ruff + mypy, ruff бота, tsc
make test            # pytest backend/bot, тесты web
make config          # валидность compose-файлов
```
CI (`.github/workflows/ci.yml`) запускает то же самое; деплой — только из `main`.
